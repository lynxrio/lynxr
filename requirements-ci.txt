# PyAV BELOW 19, deliberately. PyAV 19.0.0 (2026-09-29) removed the
# `metadata_errors` argument from av.open(), and faster-whisper (1.2.1, its
# latest release) still passes it when it decodes audio. Nothing here pinned
# av, so the 2026-10-03 worker rebuild pulled 19.0.1 and every transcription
# failed with "open() got an unexpected keyword argument 'metadata_errors'".
# That surfaced as "the video couldn't be downloaded": all 8 formats of an
# agency brief failed on 2026-10-04. Verified: av 18.1.0 accepts the argument,
# 19.0.1 raises exactly that TypeError. Lift this only once a faster-whisper
# release stops passing metadata_errors, and re-test transcription first.
av>=11,<19

# yt-dlp WITHOUT the curl-cffi extra, deliberately.
#
# curl-cffi 0.15.0 breaks the TikTok extractor outright: every TikTok URL —
# including TikTok's own official video — fails with "Unexpected response from
# webpage request", while Instagram and YouTube keep working. A real creator
# submission failed this way on 2026-08-12. Verified by bisection: same yt-dlp
# version, curl_cffi present = fail, absent = OK, on both the stable release and
# the nightly.
#
# So install plain `yt-dlp`, never `yt-dlp[default]` or `yt-dlp[curl-cffi]` —
# the extra is what drags curl-cffi in. Nothing else in this file needs it.
# Re-test TikTok before ever adding it back.
yt-dlp>=2024.1
