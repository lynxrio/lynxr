How do you write a short delivery note to send with your files?

A delivery note tells the brand what you sent, what each file is for, and what you need back from them. Keep it to a greeting, a short file list, any notes that need a decision, and one clear next step, so the person opening it can check the job without asking you anything.

Published 25 November 2026

What is a delivery note actually for?

A delivery note turns a folder of files into a finished job the brand can check in a few minutes.

The person who opens your files may not be the person who wrote the brief, or the one who approved your script when you turned the brief into a script. They need to know what they are looking at, which file answers which part of the job, and whether anything is waiting on them. Without a note, they open every file, guess, and come back to you with questions you could have answered up front.

The note is separate from how you name and package the files. How do you name and send UGC files to a brand? covers the folder and the names. The note is the short message that sits on top and explains what is inside.

What should a UGC delivery note include?

Include a greeting, a file list that maps to the brief, any decisions you made, what you need back, and the next step.

  • A one-line opener that names the job, so the message is easy to find later.
  • The file list, in the same order as the deliverables in the brief, so the brand can tick them off.
  • Anything you changed or chose yourself, such as a second hook or a swapped location, with the reason in one sentence.
  • What you need from them, such as approval, feedback, or a choice between two versions.
  • The next step and how revisions work, so nobody has to ask what happens now.

If you are unsure what the file list should hold, check it against what you should deliver at the end of a UGC job. The note only lists what is there; it never adds work the brief did not ask for.

How do you word the note so it reads quickly?

Write it as short labelled lines the brand can scan, not as a paragraph they have to read twice.

Lead with the thing they asked for, then the extras. Use the same words the brief used, so if the brief said three hook variations, your note says three hook variations, not alternative intros. Keep each file to one line: the name, what it is, and anything odd about it.

Here is a version you can copy and adapt.

Part of the noteWhat to write
OpenerHi [NAME], here are the files for [PRODUCT], as in the brief from [DATE].
File listMain video, final edit. Hook variations, three files, same body. Raw clips, in the raw folder.
Your decisionsI filmed the hook in the kitchen instead of the bathroom, because the light was steadier there.
What you needCould you confirm which hook you want to run first?
Next stepYour round of revisions is included, so send any changes together and I will turn them around by [DATE].

What do you do when something in the delivery is different from the brief?

Name the difference in the note, give the reason, and offer the fix, before the brand finds it themselves.

If a required line runs long, if a shot from the shot list did not work, or if you filmed an extra take, say so in one line. A difference the brand spots on their own reads like a mistake. The same difference explained in your note reads like a decision.

Offer them a way back. Write, for example, I can swap the kitchen hook for a bathroom take if you prefer the original plan. That turns a possible complaint into a simple choice, and it keeps the conversation inside the round of revisions you agreed. How should revisions work on a UGC job? helps you set that limit before the note goes out.

How do you end the note so the brand knows what to do next?

End with one request and one date, so the brand knows exactly what reply you are waiting for.

Avoid closing with let me know what you think. It invites a vague reply, or no reply. Ask for one specific thing instead: approval, a choice between versions, or all changes in one message. Then say when you will act on it.

  • Ask a question with a clear answer, such as which of the three hooks should run first.
  • Ask for all feedback in one message, because scattered notes are easy to miss.
  • Say how long the download link stays open, if your file service sets a limit.
  • Thank them in one line and stop.

If changes come back after you have delivered, the note gives you something to point to. The answer on handling changes a brand asks for once the files are in covers that reply.

What should you check before you hit send?

Open every link and file from the note as if you were the brand, then send it.

  • Every file in the list is in the folder, and every file in the folder is in the list.
  • The link opens without asking the brand to request access.
  • The names in the note match the file names exactly.
  • The note answers each deliverable in the brief, in the same order.
  • There is one request and one date at the end, not several.

This check takes a few minutes and saves the brand from writing back about a broken link. It also leaves a clean record of what you handed over and when, which matters if a question about the script or the files comes up weeks later.
